# Self-hosting contract (v1)

This is the shared contract for the ten parallel self-hosting agents. It is
owned by the parent integrator; **do not edit this file** in agent branches.
All agents branch from the commit that adds this document.

## Ground rules

- No new crates or `Cargo.toml` changes.
- No edits to `src/modules/mod.rs`, `src/cli.rs`, `README.md`, or
  `docs/SELF_HOSTING.md`; the parent wires modules and documents the release.
- No edits to files owned by another agent (listed below).
- Rust modules follow the existing `Value::new_object` + `runtime::native`
  pattern used by `src/modules/json.rs` and `src/modules/fs.rs`.
- Every new native function must validate its arguments and return
  `Err(String)` with an Englishmen-style message instead of panicking.
- Every new module must include `#[cfg(test)] mod tests` using
  `crate::modules::support::call_native` so it is covered by `cargo test --lib`.
- Commit your work in your assigned worktree. Report the branch name, files
  changed, tests run, and any parent-integration step needed.

## 1. `bytes` module — agent `sh-bytes-impl`

**Owns:** `src/modules/bytes.rs`, `tests/bytes_module.rs`.

A byte buffer is an Englishmen **array of numbers** in `0..=255`. All packers
return new arrays; mutating helpers return the buffer for chaining.

| Function | Contract |
| --- | --- |
| `bytes.fromString(text)` | UTF-8 bytes of `text` as a buffer. |
| `bytes.toString(buffer)` | Decode buffer as UTF-8; error on invalid UTF-8. |
| `bytes.of(...nums)` | Explicit bytes; rejects non-integers and values outside `0..=255`. |
| `bytes.length(buffer)` | Number of bytes. |
| `bytes.get(buffer, index)` | Byte at `index` (negative indexes count from the end). |
| `bytes.set(buffer, index, value)` | Set one byte, return the same buffer. |
| `bytes.concat(...buffers)` | Concatenate buffers in order. |
| `bytes.slice(buffer, start, end?)` | Half-open slice; `end` defaults to length. |
| `bytes.copy(buffer)` | Independent copy. |
| `bytes.fromHex(text)` | Parse `aa bb cc` / `aabbcc` style hex into a buffer. |
| `bytes.toHex(buffer)` | Lowercase hex, two digits per byte, space-separated. |
| `bytes.u8(n)`, `bytes.u16(n)`, `bytes.u32(n)`, `bytes.u64(n)` | Unsigned little-endian packing. |
| `bytes.i16(n)`, `bytes.i32(n)`, `bytes.i64(n)` | Signed two's-complement little-endian packing. |
| `bytes.f64(n)` | IEEE-754 little-endian packing. |
| `bytes.read(path)` | Read a file as a buffer (binary-safe). |
| `bytes.write(path, buffer)` | Write a buffer to a file; return `true`. |

`bytes.read`/`write` are the binary counterparts of `fs.read`/`fs.write`.

## 2. `emb` module — agent `sh-emb-impl`

**Owns:** `src/modules/emb.rs`, `tests/emb_module.rs`.

**Contract:** `emb.write(path, ir)` writes bytes that are byte-for-byte
compatible with `bytecode::serialize`. `emb.encode(ir)` returns the same bytes
as a buffer; `emb.write` may use `std::fs::write` directly (the `bytes` module
is implemented in a separate branch). The IR is an Englishmen object:

```js
{
  version: 2,               // must equal the VM's EMB_VERSION
  constants: [              // any order; index is the constant pool index
    {tag: "number", value: 1},
    {tag: "string", value: "hi"},
    {tag: "bool", value: true},
    {tag: "null"}
  ],
  functions: [              // nested chunks; same shape minus "version"
    {name: "f", params: ["a"], chunk: {constants: [], functions: [], code: []}}
  ],
  code: [
    {op: "LoadConst", a: 0, b: 0, line: 1, col: 1}
  ]
}
```

Top-level IR has `version`, `constants`, `functions`, `code`. Nested `chunk`
objects have only `constants`, `functions`, `code`. `op` accepts the Rust
`Op` variant names below; `a`/`b` default to `0`, `line`/`col` default to `1`.
Unknown constant tags, unknown op names, non-integral operands, and version
mismatches are errors.

Opcode tags (must match `bytecode::encode_op`):

```
LoadConst=0 Pop=1 GetVar=2 SetVar=3 DefineVar=4 GetProp=5 SetProp=6
GetVarOrObject=7 GetPropOrObject=8 GetIndex=9 SetIndex=10 MakeArray=11
MakeObject=12 MakeClosure=13 Call=14 MethodCall=15 Say=16 Add=17 Sub=18
Mul=19 Div=20 Mod=21 FloorDiv=42 Pow=43 BitAnd=44 BitOr=45 BitXor=46
Shl=47 Shr=48 Eq=22 NotEq=23 Gt=24 Lt=25 GtEq=26 LtEq=27 Neg=28 Not=29
BitNot=49 ToBool=30 Jump=31 JumpIfFalse=32 JumpIfFalsePeek=33
JumpIfTruePeek=34 RepeatSetup=35 RepeatNext=36 IterSetup=37 IterNext=38
Return=39 ReturnNull=40 Import=41 Dup=50 Rotate=51 GetPropKeep=52
GetIndexKeep=53 JumpIfNullPeek=54
```

Also expose `emb.encodeOp(name)` -> numeric tag (useful for `.enm` emitters)
and `emb.magic()` -> `"EMBC"`, `emb.version()` -> `2`.

**Verification:** `bytecode::deserialize(&emb.encode(ir))` must succeed and
round-trip constants, functions, and instructions. Add a Rust unit test that
does this with a multi-function IR containing every constant tag and at least
one instruction from each operand shape.

## 3. `project` module — agent `sh-project-impl`

**Owns:** `src/modules/project.rs`, `tests/project_module.rs`.

Mirror `src/config.rs` in Englishmen-callable form.

| Function | Contract |
| --- | --- |
| `project.parse(text)` | Parse `.emc` text into `{root: object, sections: object}`. |
| `project.load(path?)` | Parse a file; default path is `englishmen.emc` in `fs.cwd()`. |
| `project.get(config, key)` | Root value or `null`. |
| `project.section(config, name)` | Section object or empty object. |
| `project.name(config)`, `project.version(config)`, `project.main(config)` | Shortcuts for root keys. |
| `project.default(name)` | Same text as `config::default_emc(name)`. |
| `project.write(path, config)` | Serialize config back to `.emc` text and write it; return `true`. |

Parsing rules: trim lines, ignore blanks and `#` comments, `[section]` starts a
section, `key=value` stores a trimmed value, and surrounding double quotes are
removed. Serialization must preserve root keys then sections with `[name]`
headers, one `key = "value"` per line. Use `BTreeMap` ordering for stable
output. Support `Value::Number/Bool/Null` by formatting them as bare values.

## 4. `.enm` lexer — agent `sh-enm-lexer`

**Owns:** `selfhost/lexer.enm`, `tests/selfhost_lexer.rs`.

Write an Englishmen lexer that mirrors `src/lexer.rs` closely enough for the
bundled examples. It must expose `function lex(source)` returning an array of
token objects:

```js
{type: "Identifier", value: "name", line: 1, col: 1}
```

For `Number`, `value` is a number. For `String`, `value` is the decoded string.
For `Interpolated`, `value` is an array of `{type:"Literal"|"Expr", value:...}`
where `Expr` holds a token array. All other tokens use their Rust `Token`
variant name as `type` (`If`, `End`, `PlusPlus`, `CompoundAssign`, `Newline`,
`Eof`, ...); compound assignment tokens include `op` (`+`, `-`, `*`, `/`, `%`,
`**`, `//`, `&`, `|`, `^`, `<<`, `>>`).

Handle: whitespace, `$- ... -$` comments, `//` comments only when not floor
division, identifiers, decimal/hex/binary/exponent numbers, normal and
interpolated strings with the language's escapes, two-character operators,
and line/column tracking. `tests/selfhost_lexer.rs` runs `em run
selfhost/lexer.enm <file>` on every file in `examples/` and asserts
it exits successfully and emits a JSON token array via `json.encode`.

## 5. `.enm` parser — agent `sh-enm-parser`

**Owns:** `selfhost/parser.enm`, `tests/selfhost_parser.rs`.

Write `function parse(tokens)` in Englishmen. It consumes the token objects
from `selfhost/lexer.enm` and returns the **AST object shape** in the contract
below. It must support every `Stmt` and `Expr` variant in `src/ast.rs`,
including `break`/`continue` inside loops, chained method calls, binary
precedence, `and`/`or`, ternary, `??`, `**` (right-associative), `//`, bitwise
operators, postfix `++`/`--`, compound assignment, and interpolated strings
lowered exactly as `src/parser.rs::parse_interpolated` does.

`tests/selfhost_parser.rs` runs `em run selfhost/parser.enm <file>`
for every `examples/*.enm` and checks the output is a JSON object with a
`statements` array. Add at least one negative test that returns a structured
error object `{error: string, line: number, col: number}`.

## 6. AST JSON + Rust emitter — agent `sh-ast-json`

**Owns:** `src/ast_json.rs`, `tests/ast_json.rs`, `docs/selfhost/AST_JSON.md`.

Implement `pub fn to_json(statements: &[Stmt]) -> Result<Value, String>` using
`Value` objects/arrays so `json.encode` can serialize it deterministically.
The parent will wire `em build <file> --emit ast-json` to print
`json::encode(&to_json(...))` plus a newline; do not edit `src/cli.rs`.

AST JSON schema (version 1):

```js
{
  "version": 1,
  "statements": [StmtJSON, ...]
}
```

Span JSON is `{"line": n, "col": n}` (no end column).

StmtJSON variants:

```js
{kind:"Assign", span:S, target:AssignableJSON, value:ExprJSON}
{kind:"CompoundAssign", span:S, target:AssignableJSON, op:Op, value:ExprJSON}
{kind:"ExprStmt", span:S, expr:ExprJSON}
{kind:"If", span:S, branches:[{condition:ExprJSON, body:[StmtJSON,...]},...], else:[StmtJSON,...]|null}
{kind:"FunctionDef", span:S, name:"f", params:["a",...], body:[StmtJSON,...]}
{kind:"Return", span:S, value:ExprJSON|null}
{kind:"Repeat", span:S, count:ExprJSON, body:[StmtJSON,...]}
{kind:"While", span:S, condition:ExprJSON, body:[StmtJSON,...]}
{kind:"ForIn", span:S, name:"x", iterable:ExprJSON, body:[StmtJSON,...]}
{kind:"Break", span:S} {kind:"Continue", span:S}
{kind:"Import", span:S, name:"json"}
```

AssignableJSON variants:

```js
{kind:"Variable", name:"x"}
{kind:"Property", base:ExprJSON, name:"a"}
{kind:"Index", base:ExprJSON, index:ExprJSON}
```

ExprJSON variants:

```js
{kind:"Number", value:1}
{kind:"String", value:"x"}
{kind:"Bool", value:true}
{kind:"Null"}
{kind:"Variable", name:"x"}
{kind:"PropertyAccess", base:ExprJSON, name:"a"}
{kind:"Index", base:ExprJSON, index:ExprJSON}
{kind:"Array", items:[ExprJSON,...]}
{kind:"Object", fields:[{name:"a", value:ExprJSON},...]}
{kind:"Call", callee:ExprJSON, args:[ExprJSON,...]}
{kind:"MethodCall", receiver:ExprJSON, name:"m", args:[ExprJSON,...]}
{kind:"Binary", op:Op, left:ExprJSON, right:ExprJSON, span:S}
{kind:"Unary", op:Op, operand:ExprJSON, span:S}
{kind:"Ternary", condition:ExprJSON, whenTrue:ExprJSON, whenFalse:ExprJSON, span:S}
{kind:"Postfix", op:"++"|"--", target:ExprJSON, span:S}
```

Operator strings: `+ - * / % // ** & | ^ << >> == != > < >= <= and or ??`;
unary strings: `-`, `not`, `~`. Object fields keep source order (use an
array of `{name,value}` pairs, not an object, so duplicates survive).

`docs/selfhost/AST_JSON.md` is the human-readable schema. Unit tests must cover
every statement and expression variant and assert `json::encode` output is
stable across runs.

## 7. `.enm` emitter — agent `sh-enm-emitter`

**Owns:** `selfhost/emit.enm`, `examples/selfhost_pipeline.enm`.

Write `function emit(ast)` in Englishmen that converts the AST object shape
above into compact JSON text byte-for-byte compatible with
`json.encode(crate::ast_json::to_json(statements))`. It must preserve field
order exactly as the schema lists it, escape strings the same way as the
`json` module (`\"`, `\\`, `\n`, `\r`, `\t`, control chars as `\u00XX`), and
emit numbers with `format_number` rules (integers without `.0`).

Also add `examples/selfhost_pipeline.enm`, a runnable Englishmen program that
imports `bytes`, `emb`, `project`, `json`, `fs`, reads a source file from
`args[0]`, demonstrates parsing a trivial manifest with `project.parse`, packs
a little-endian header with `bytes.u32`, and writes a tiny `.emb` file with
`emb.write` using a `LoadConst` instruction. It must run successfully on both
backends (`em run` and `em run --interpret`).

## 8. Bootstrap runner — agent `sh-bootstrap-runner`

**Owns:** `selfhost/compiler.enm`, `tests/selfhost_bootstrap.rs`,
`docs/selfhost/BOOTSTRAP.md`.

Write `selfhost/compiler.enm`: the self-contained CLI entry point. Englishmen
does not yet support importing local `.enm` files, so inline the lexer, parser,
and emitter functions in this one file (they may also live separately in the
other agents' branches). It reads a source file path from `args`, lexes it,
parses it, emits AST JSON, and prints exactly one JSON line. It must use
`fs.read` and `json` only for I/O; no Rust-side helpers.

`tests/selfhost_bootstrap.rs` must, for every `examples/*.enm`, run:

1. `em build <example> --emit ast-json` (wired by the parent), and
2. `em run selfhost/compiler.enm <example>`

and assert the stdout JSON is byte-identical after trimming trailing newlines.
The test must be skipped with a clear `eprintln!` if `selfhost/compiler.enm`
still contains the literal `TODO`. `docs/selfhost/BOOTSTRAP.md` documents the
bootstrap command, current caveats, and how to add a new example.

## 9. Bytes docs/spec — agent `sh-bytes-spec`

## 10. Manifest + EMB docs/spec — agent `sh-manifest-spec`

**Owns:** `docs/selfhost/EMB_AND_MANIFEST.md`, `examples/emb_manifest.enm`,
`tests/emb_manifest_example.rs`, `tests/emb_roundtrip.rs`.

Document the `emb` IR and `project` manifest API from this contract, including
a worked example that writes a `.emb` from Englishmen and loads it with
`em run-fixed`. Add `examples/emb_manifest.enm` that parses a sample `.emc`,
writes a minimal `.emb`, and prints the manifest name plus the byte length.
Add `tests/emb_manifest_example.rs` (both backends) and
`tests/emb_roundtrip.rs`, which writes an IR from Rust `Value`s through the
`emb` module's native functions, calls `bytecode::deserialize`, and asserts the
chunk round-trips.

## Parent integration checklist

The parent will, in order:

1. Cherry-pick/merge `bytes`, `emb`, `project` implementation branches.
2. Register the three modules in `src/modules/mod.rs` (`STD_MODULES` and
   `load_module`) and update the CLI module catalogue.
3. Add `src/ast_json.rs` and wire `--emit ast-json`.
4. Cherry-pick/merge `.enm` lexer, parser, emitter, then bootstrap runner.
5. Run `cargo test --all-targets` and `em fmt --check` on all `.enm` files.
6. Update `docs/SELF_HOSTING.md` and the release notes.

If a feature cannot be completed, leave a precise `TODO` and report it; do not
fake success or weaken a test.
